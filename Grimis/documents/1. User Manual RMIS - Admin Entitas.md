# User Manual RMIS - Admin Entitas (K/L/P/BU)

## Overview
Dokumen ini merinci persyaratan teknis dan alur antarmuka (UI Flow) bagi **Admin Entitas** dalam aplikasi **Risk Management Information System (RMIS)**. Admin Entitas bertanggung jawab atas konfigurasi sistem, standarisasi parameter, dan manajemen pengguna di tingkat instansi.

---

## 1. Navigasi & Antarmuka Utama (Visual Layout)
Aplikasi menggunakan tata letak standar untuk memudahkan navigasi:
- **Sidebar (Sisi Kiri)**: Menu utama navigasi (Dashboard, Parameter, Pengelolaan, Approval).
- **Header (Sisi Atas)**: Informasi user, Tahun Pengelolaan, Unit Kerja, dan Menu Profil.
- **Action Icons (...)**: Tombol titik tiga pada kolom "Tindakan" untuk opsi Detail, Ubah, atau Hapus.
- **Status Badges**: Penanda warna untuk status approval (e.g., Kuning: Menunggu, Hijau: Terverifikasi, Merah: Gagal).

---

## 2. Manajemen Akses & Login

### Alur Visual Login
1. **Akses URL**: Buka [https://rmis.bpkp.go.id](https://rmis.bpkp.go.id).
2. **Input Kredensial [02, 03, 04]**: Masukkan Email dan Password yang dikirim via sistem (cek email [01]).
3. **Keamanan [05]**: Centang reCAPTCHA. Jika muncul tantangan gambar (Uji Turing), pilih gambar sesuai instruksi.
4. **Masuk [06, 07]**: Klik tombol "Masuk" dan pilih "Tahun Pengelolaan" pada pop-up yang muncul.

### Manajemen Akun (Pojok Kanan Atas)
- **Ubah Password [01, 02]**: Klik Nama User -> Pilih "Ubah Password" -> Isi Password Lama & Baru.
- **Lupa Password [01-05]**: Klik "Lupa Password" di hal. login -> Input Email -> Cek Link Reset di Email.

---

## 3. Konfigurasi Parameter (Master Data)

### Setting Matriks Risiko [01-03]
Admin harus menentukan "Aturan Main" penilaian risiko:
1. **Navigasi**: Menu Parameter -> Setting Matriks Risiko.
2. **Skala**: Pilih format matriks (3x3, 4x4, atau 5x5).
3. **Template**: Gunakan "Salin Template" untuk efisiensi, atau atur manual.
4. **Warna Heatmap [01-04]**: Klik kotak pada matriks untuk menentukan warna berdasarkan nilai (Dampak x Frekuensi). Simpan Template setelah selesai.

### Standarisasi Kriteria (Langkah A, B, C)
Untuk setiap level Frekuensi dan Dampak, Admin wajib mengisi:
- **Level/Kategori (Huruf A)**: Nama tingkatan (e.g., Sangat Tinggi).
- **Penjelasan (Huruf B)**: Deskripsi kualitatif tingkatan tersebut.
- **Kriteria (Huruf C)**: Indikator kuantitatif/spesifik. Gunakan ikon (+) untuk menambah atau (-) untuk menghapus baris kriteria.

### Struktur Organisasi & Pengguna [01-08]
1. **Input Unit**: Tambah Unit Kerja dengan pola *Cascading* (Induk -> Anak).
2. **Detail Unit**: Isi Kode, Nama Lengkap, Nama Pendek, Nama Pimpinan, dan Jabatan.
3. **Selera Risiko**: Tetapkan nilai ambang batas (tidak boleh lebih tinggi dari unit induk).
4. **Manajemen Pengguna [01-05]**: Daftarkan email personil dan tentukan perannya (Pemilik, Pengelola, atau Pengawas).

### Kamus & Konteks (Standarisasi Narasi)
- **Kategori Risiko**: Master data jenis risiko (Strategis, Operasional, dll).
- **Jenis Konteks**: Master data Sasaran atau Proses Bisnis (Probis).
- **Kamus Risiko**: Pembakuan narasi risiko untuk menghindari duplikasi (e.g., menyeragamkan istilah "Penyuapan" di seluruh unit).
- **Fitur Import**: Tersedia template Excel untuk pengisian massal Konteks, Indikator, dan Kamus Risiko.

---

## 4. Alur Persetujuan (Approval Flow)
Admin Entitas bertindak sebagai validator atas usulan dari Unit Kerja:
1. **Approval Kamus/Konteks/Indikator**:
   - Cek daftar usulan dengan status "Menunggu Proses Verifikasi".
   - Klik ikon (...) -> Pilih Setuju atau Tolak.
   - **Setuju dengan Penyesuaian**: Admin dapat memperbaiki narasi usulan sebelum diterbitkan ke Kamus Nasional.
2. **Otomasi Approval**: Terdapat tombol toggle di sisi kanan atas untuk mengaktifkan/nonaktifkan persetujuan manual. Jika nonaktif, usulan unit akan langsung disetujui sistem.

---

## 5. Monitoring & Dashboard

### Dashboard Utama [01-07]
Visualisasi data real-time meliputi:
- **Populasi Risiko**: Jumlah total risiko teridentifikasi.
- **Heat Map**: Sebaran risiko pada matriks warna.
- **Efektivitas Pengendalian**: Status RTP dan pengendalian yang ada.

### Advanced Dashboard [01-02]
- Informasi detail mengenai **Pencatatan Keterjadian** (Loss Event Database).
- Sebaran risiko berdasarkan **Tujuan SPIP** dan **Jenis Konteks**.
- Fitur cetak laporan tersedia melalui ikon titik tiga (...) di setiap widget dashboard.

---

## 6. Penutup & Epilog
Admin Entitas memegang peran krusial dalam memastikan data parameter akurat sebelum unit kerja mulai melakukan pengelolaan risiko. Konsistensi dalam pengisian parameter tahunan akan menentukan kualitas pelaporan risiko di tingkat instansi.
